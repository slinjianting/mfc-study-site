## 2. 信息架构

采用“一周一个 `week3-proofs.html` + 页内多 proof section”。目录按 **station 顺序，再按 lesson.number** 排列；不按单个大全局序号，避免和主学习站课号混淆。

目录只显示有证明数据的 6 条：

```text
Taylor 基础
  01 高阶导数与 Taylor 多项式
余项与误差
  05 显式误差界与数值保证
  06 Big-O 局部误差与 Richardson 外推
可积性
  11 连续函数可积与 Dirichlet 反例
  12 积分性质与单点修改
FTC
  13 累积函数与微积分基本定理 I
```

路由采用 URL hash，单文件内切换 section：

- `week3-proofs.html#proof-higher-derivatives-taylor`
- 无 hash 时默认选第一条 proof。
- 非法 hash 回退第一条，并在目录标记当前项。
- 步骤切换和模式切换不写入 URL，避免每一步都污染浏览器历史。
- 切 proof 使用 `history.replaceState` 更新 hash，再切 section；返回键仍回到上一页面。

## 3. 数据 schema

推荐新建 `week3/week3-proofs.js`，不并入 `week3-lessons.js`。理由：证明页是一周一个聚合页面，一个 proof 对应一个 lesson；数据生命周期、加载页面和状态存储都与 16 课正文不同。独立文件也让主学习站只读取 proof 元信息，不必解析大段步骤。

推荐使用“一份 canonical steps + exam/full 两个 stepIds 顺序”的模型，而不是两套完整 steps 数组，也不是只在每步写 `depth`。

```js
window.MFC_WEEK3_PROOFS = {
  weekId: "week3",
  proofPage: "week3-proofs.html",
  notes: [{
    id: "note-higher-derivative",
    kind: "definition", // definition | theorem | symbol | identity
    termZh: "k 阶导数",
    termEn: "k-th derivative",
    summaryZh: "……",
    summaryEn: "……",
    source: { label: "Definition 7.1", pages: "p.3–4" },
    symbol: "f⁽ᵏ⁾(a)" // 可选；可回链 lesson.symbols
  }],
  proofs: [{
    id: "proof-higher-derivatives-taylor",
    lessonId: "higher-derivatives-taylor",
    station: "taylor-core",
    lessonNumber: "01",
    titleZh: "Taylor 系数构造与导数匹配",
    titleEn: "Constructing Taylor coefficients by derivative matching",
    claimZh: "……",
    claimEn: "……",
    source: { label: "Definition 7.1 construction", pages: "p.3–4" },
    noteIds: ["note-expansion-point", "note-higher-derivative"],
    steps: [{
      id: "differentiate-k",
      titleZh: "第 k 次求导只留下目标项",
      titleEn: "Only the k-th term survives",
      formula: "Pₙ⁽ᵏ⁾(a) = k! cₖ",
      reasonZh: "低次项已归零，高次项仍含 x−a 并在 a 点归零。",
      reasonEn: "Lower terms vanish and higher terms still contain x−a.",
      noteIds: ["note-higher-derivative", "note-factorial"],
      source: { label: "Definition 7.1 construction", pages: "p.3" },
      fullOnly: false, // 仅用于提示，最终顺序以 modes.*.stepIds 为准
      modeOverrides: {} // 可选；给同一 canonical step 的考试版短理由
    }],
    modes: {
      exam: {
        labelZh: "考场版",
        labelEn: "Exam",
        stepIds: ["goal", "differentiate-k", "match", "solve", "conclusion"]
      },
      full: {
        labelZh: "完整版",
        labelEn: "Full",
        stepIds: ["goal", "candidate", "evaluate-zero", "differentiate-once",
          "differentiate-k", "factorial", "match", "solve", "conclusion"]
      }
    },
    defaultMode: "exam",
    entryHref: "week3-proofs.html#proof-higher-derivatives-taylor"
  }]
};
```

约束：

- `lessonId` 必须能精确匹配 `window.MFC_WEEK3_LESSONS[].id`。
- 每个 step 固定拥有 `titleZh/titleEn`、`formula`、`reasonZh/reasonEn`、`noteIds`、`source`。
- `formula` 只写符号；极限写 `lim h→0`，不放中文口号。
- `modes.exam.stepIds` 长度限制 3–5；`modes.full.stepIds` 长度限制 8–10。
- 每个 mode 的 stepIds 必须唯一；full 未包含的 canonical step 就是 full-only。
- proofNote 可以引用 lesson 已有的 `symbols` 值，但正式证明解释放 `proofNotes`，不把 `symbols` 当作定理出处。

## 5. 交互状态机

每条 proof 的每个 mode 各存独立状态：

```text
proofState[proofId][mode] = {
  revealedCount: 0..stepIds.length,
  activeStepId: string,
  expandedAll: boolean
}
```

`revealedCount` 表示“已有多少个步骤展开推理”。默认 0，只显示第 1 个步骤的标题、目标和右侧旁注；步骤正文隐藏。

| 操作 | 状态变化 | 边界 |
| --- | --- | --- |
| 默认打开 | `revealedCount=0`，`activeStepId=第1步`，只露第1步目标 | 不展开任何 `.proof-step-body` |
| 下一步 | `revealedCount+1`，`activeStepId=刚展开的步骤` | 到达最后一步后按钮禁用 |
| 上一步 | `revealedCount-1`，`activeStepId` 回到上一可见步骤 | 0 时禁用；不可低于 0 |
| 全展开 | `revealedCount=len`，`expandedAll=true`，active 可保留 | 所有步骤正文和旁注切换源可用 |
| 收起 | `revealedCount=0`，`expandedAll=false`，active 回第1步 | 回到初始态 |
| exam → full | 保存 exam 状态，恢复 full 自己的状态；无历史则从 0 开始 | 不把 exam 展开数直接套到 full |
| full → exam | 保存 full 状态；exam full-only 步骤立即隐藏 | full-only 已展开状态保留在 full 快照中，不迁移 |
| 切 proof | 保存当前 proof 两档状态，读取目标 proof 状态 | hash 无效时回退第一条 proof |
| 点击 step 标题 | 只更新 `activeStepId`，切换右侧旁注 | 不隐式跳过后续步骤；不展开未揭示正文 |

持久化：在现有 `mfc-learning:v2` 的 `weeks.week3.proofProgress` 下保存 `activeProofId` 和每个 proof 的 mode 状态。重置 Week 3 时一起清除，主题与语言不受影响。

## 6. 双档共存策略

推荐只维护一份 canonical `steps`，用 `modes.exam.stepIds` 与 `modes.full.stepIds` 控制顺序和可见性。

- 两档共用步骤只写一次，理由和式子不会漂移。
- 完整版多出的中间步骤只存在于 canonical steps，并由 full stepIds 引用。
- 考场版需要更短理由时，在 step 内使用 `modeOverrides.exam.reasonZh/reasonEn` 覆盖显示，不复制整步。
- 步骤标题和公式仍来自同一 canonical step，避免考场版与完整版出现不同数学结论。
- 默认只显示 exam 档；用户上次选择的 mode 可持久化。
- 切换档位时按 mode 独立保存 state，已展开的 full-only 步骤只保留在 full 状态，不污染 exam。
- 入口按钮步数读取 `modes.exam.stepIds.length`，例如“看证明 · 5 步”；proof 页当前档位显示实际 `stepIds.length`。

## 7. 右侧旁注

不复用 `symbols` 作为证明旁注的唯一来源。`symbols` 服务于 lesson 的快速符号解码，缺少定理/定义依据。新增周级 `proofNotes`，step 通过 `noteIds` 引用。

每条 proofNote：

```text
id
kind: definition | theorem | symbol | identity
termZh / termEn
summaryZh / summaryEn
source: { label, pages }
symbol?: 可回链 lesson.symbols 的符号
```

规则：

- `step.noteIds` 是“这一步用了哪几条”的唯一事实来源。
- 右侧只显示当前 `activeStepId` 对应的 notes；同一步引用多个知识点时按 noteIds 顺序列出。
- 每条至少显示“名词、一句话、讲义编号与页码”。
- 若 step 没有 noteIds，右栏显示“仅使用上一步已引入的记号”，不伪造新定理。
- proofNote 只解释证明使用关系，不复制整段教材；复杂术语可额外链接回主学习站 lesson。

## 9. 样板：第 01 课完整内容规格

结果：构造 degree-n Taylor polynomial

```text
Tₙ[f;a](x) = Σ(k=0→n) f⁽ᵏ⁾(a)/k! · (x−a)ᵏ
```

并证明它匹配 0 到 n 阶导数，且系数唯一。全部内容来自讲义 p.3–4，无外部引理，无【待核对】项。

### 考场版 5 步

| 步骤 | 标题 | 式子 | 一句话理由 | noteIds |
| --- | --- | --- | --- | --- |
| `goal` | 目标与候选 | `Pₙ(x)=Σ(k=0→n)cₖ(x−a)ᵏ; Pₙ⁽ᵏ⁾(a)=f⁽ᵏ⁾(a)` | 用 n+1 个待定系数匹配 n+1 组局部导数数据 | `note-finite-polynomial`, `note-expansion-point` |
| `differentiate-k` | 只留下第 k 项 | `Pₙ⁽ᵏ⁾(a)=k!cₖ` | 低次项归零，高次项仍含 x−a 也归零，只剩 k 次项 | `note-higher-derivative`, `note-power-rule` |
| `match` | 代入导数数据 | `k!cₖ=f⁽ᵏ⁾(a)` | 每个 k 都由匹配条件唯一决定一个系数 | `note-derivative-matching` |
| `solve` | 解出系数 | `cₖ=f⁽ᵏ⁾(a)/k!` | k! 非零，可直接相除 | `note-factorial` |
| `conclusion` | 得到 Taylor 多项式 | `Tₙ(x)=Σ f⁽ᵏ⁾(a)/k!(x−a)ᵏ` | 代回候选式即构造完成，并因每步可逆而唯一 | `note-finite-polynomial`, `note-uniqueness` |

### 完整版 9 步

| 步骤 | 标题 | 式子 | 一句话理由 | noteIds |
| --- | --- | --- | --- | --- |
| `goal` | 目标声明 | `Pₙ⁽ᵏ⁾(a)=f⁽ᵏ⁾(a), 0≤k≤n` | 目标是复制展开点的 n+1 组导数数据 | `note-derivative-matching` |
| `candidate` | 写成局部幂形式 | `Pₙ(x)=c₀+c₁(x−a)+…+cₙ(x−a)ⁿ` | 用 x−a 的幂使 a 点求导结构最清楚 | `note-expansion-point` |
| `evaluate-zero` | 先求 c0 | `Pₙ(a)=c₀; f(a)=c₀` | 除常数项外所有 (x−a)ᵏ 在 a 点为 0 | `note-power-rule` |
| `differentiate-once` | 求 c1 | `P′ₙ(a)=c₁; f′(a)=c₁` | 一次求导消去常数项，高次项仍含 x−a | `note-power-rule` |
| `differentiate-k` | 一般第 k 次求导 | `Pₙ⁽ᵏ⁾(a)=k!cₖ` | 低于 k 次项消去，高于 k 次项在 a 点归零 | `note-higher-derivative` |
| `factorial` | 提取常数 | `dᵏ/dxᵏ((x−a)ᵏ)=k!` | k 次连续求导产生 k! | `note-factorial` |
| `match` | 施加匹配条件 | `Pₙ⁽ᵏ⁾(a)=f⁽ᵏ⁾(a)` | 这是 Taylor 局部匹配的定义要求 | `note-derivative-matching` |
| `solve` | 唯一解系数 | `k!cₖ=f⁽ᵏ⁾(a) ⇒ cₖ=f⁽ᵏ⁾(a)/k!` | 每个系数方程独立且 k! 非零 | `note-uniqueness` |
| `conclusion` | 写出定义并收口 | `Tₙ[f;a](x)=Σ(k=0→n)f⁽ᵏ⁾(a)/k!(x−a)ᵏ` | 候选系数全部确定，构造与唯一性同时完成 | `note-finite-polynomial`, `note-uniqueness` |

第 01 课 proofNotes 至少包含：

- `note-expansion-point`：展开点 a；`x−a` 是相对位移；p.3。
- `note-finite-polynomial`：Tₙ 是次数不超过 n 的有限多项式；不是无限级数；Definition 7.1，p.3–4。
- `note-higher-derivative`：f⁽ᵏ⁾ 是 k 阶导数，不是 k 次幂；p.3。
- `note-power-rule`：对 `(x−a)ᵏ` 求导，高次项在 a 点仍为 0；p.3。
- `note-factorial`：k 次项第 k 次求导出现 k!；p.3。
- `note-derivative-matching`：Tₙ⁽ᵏ⁾(a)=f⁽ᵏ⁾(a)；p.4。
- `note-uniqueness`：系数方程唯一确定 cₖ；p.4。

其余 5 条 proof 之后只补数据，不在这份文档逐项展开：

- `lagrange-error-bounds`：Theorem 7.9 → 取绝对值与 M → Corollary 7.10；建议考场 4 步、完整 8 步。
- `big-o-richardson`：Definition 7.16 → 加法三角不等式 → 数乘 → 三个直接后果；建议考场 4 步、完整 8 步。
- `continuous-dirichlet`：固定任意 partition → mi=0、Mi=1 → 上下和差 b−a → 不可积；建议考场 4 步、完整 8 步。
- `integral-properties`：h=g−f → 单点非零且有界 → 隔离 c 的小区间 → 2Kℓ 控制 gap → 积分相等；建议考场 5 步、完整 9 步。
- `ftc-part-one`：差商写为短区间平均 → 减 f(x) → 连续性给 δ → 绝对积分界 → 差商趋 0；建议考场 5 步、完整 9 步。

## 12. 风险与未决问题

1. **“有 theorem 字段”与“讲义有证明”不是同一条件。**  
   风险：若按字段自动开入口，会把 Lagrange 余项、Darboux criterion、FTC II 等未证明定理做成空证明。  
   建议：入口只认 `week3-proofs.js` 中真实的 proof 数据。此项由我按已确认规则自行决定。

2. **考试版删减可能删掉评分点。**  
   风险：同一 canonical step 的考试版理由如果压得过短，学生只抄结论不会写前提。  
   建议：exam 至少保留“目标、关键推导、代入、结论”，用 `modeOverrides` 缩短理由而不删步骤；此项先由我起草，最终需用户按课程评分标准拍板。

3. **定理陈述不证明的课程是否要显示“讲义未证明”。**  
   风险：用户可能期望所有 theorem 都有入口；完全不提示会被误解为遗漏。  
   建议：本轮不新增入口；若需要，可后续用 disabled 状态“讲义仅陈述，未证明”。此项需要用户拍板。

4. **中英证明术语一致性。**  
   风险：证明页若只写中文，语言模式会失去 1:1；若逐句硬译，又可能改变数学含义。  
   建议：schema 保留双语 title/reason/note；公式保持符号；术语按讲义英文原词。此项由我自行决定，但需在交付前人工核对。

5. **旁注右栏在窄屏的空间。**  
   风险：固定宽旁注若直接堆到底部，会离开当前步骤，破坏阅读上下文。  
   建议：DOM 把 note panel 放在所属 step row 内，桌面右列、移动端同一步骤下方。此项由我自行决定。

6. **证明页状态增长与旧存储兼容。**  
   风险：直接在 `proofProgress` 中塞多种状态可能与现有 `mfc-learning:v2` 更新逻辑冲突。  
   建议：仅新增可选 `weeks.week3.proofProgress`，通过现有 `MFC_STORE.updateWeek` 保存；不新建 localStorage key。此项由我自行决定。
